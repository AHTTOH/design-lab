# 인수인계서: AFTER DARK 퀄리티 재현법

> 작성: 2026-09-28 (Opus 5.5 세션, StateProof 해커톤 제출 직후 디자인 연습)
> 목적: 다음 세션이 이 레포나 다른 프로젝트에서 같은 수준의 인터랙션 페이지를 다시 만들 수 있게 한다.
> 결과물: `stardust/`, `after-dark-1/` ~ `after-dark-5/`. 공개 주소 https://ahttoh.github.io/design-lab/

## 0. 한 줄 요약

신영환이 "좆된다, 이거지"라고 반응한 지점은 **스크롤에 묶인 실시간 그래픽**(셰이더, 파티클 모프, 영상 리빌)이다. 정적인 카드 레이아웃은 아무리 다듬어도 그 반응이 안 나온다.
그래픽의 재료(이미지·영상)는 전부 직접 생성했다. 재료 생성이 막히면 퀄리티가 바로 떨어진다.

## 1. 신영환 취향 (실제 발언에서 뽑음)

좋아한 것
- 스크롤을 내리면 화면이 반응하는 연출. "1번 사이트처럼 스크롤 내리면 애니메이션 되는 거"
- 별가루가 휠을 따라오는 것, 파티클이 모양을 바꾸는 것, 글자가 해독되듯 바뀌는 것
- **길게 내려야 끝나는 페이지.** "스크롤 한 1분은 드르륵 내려야 끝날 정도로"
- 영상을 배경으로 쓰는 것. "동영상 팍팍 써도 돼"
- 검정 바탕 + 원색 계열 네온(코발트, 바이올렛, 마젠타, 라임)

싫어한 것
- **화면에 프레임 번호·로딩 개수·장면 카운터를 띄우는 것**(2026-09-28, "192 같은 숫자 노출시키지 마"). IV 의 `001 / 192` 카운터와 `000/192` 로딩 숫자, V 갤러리의 `01 / 05` 를 지웠다. 로딩은 숫자 없는 막대로만 보인다
- **장면이 너무 빨리 넘어가는 것.** "스크롤 한두 번 만에 졸라 큰 폰트들이 슉슉 바뀌어 버려서" → 장면 하나에 최소 350vh 이상 준다
- **V 도 "너무 순식간"이었다(2026-09-28).** 4,850vh 에서 "한 스크롤당 일어나는 일의 간격을 늘려 달라"는 요청을 받아 `--scroll-stretch: 2.5` 로 전 장면을 2.5배 늘렸다(문서 높이 43,650px → 109,125px, 화면 121장). 휠 감도(`wheelMultiplier`)는 낮추지 않았다. 낮추면 스크롤 속도에 반응하는 연출(리퀴드 글자, 색수차, 중력)까지 약해진다
- 크림·아이보리·회백색 배경 (레퍼런스 3번 DarkPool 을 "제일 좆같다"고 함)
- 밋밋한 것, AI 가 만든 티가 나는 것, "16:9 피피티 슬라이드 느낌"
- 긴 부연 설명 문장. 화면에 안내문·부제를 자동으로 붙이지 않는다(`claude-rules/rules/web/design-quality.md` 1절)

## 3. 작업 순서 (이 순서가 퀄리티를 만들었다)

1. **재료부터 만든다.** 코드 전에 이미지 4~7장, 영상 3개를 생성한다(4절). 재료 없이 CSS 그라데이션으로 때우면 바로 AI 슬롭이 된다.
2. **장면 목록을 먼저 쓴다.** 장면마다 이름, 길이(vh), 핵심 기법 하나. III 은 14장면, 총 약 6,600vh(데스크톱 66화면)다.
3. **장면 하나에 대담한 기법 하나.** 한 장면에 셰이더와 파티클과 영상을 다 넣지 않는다.
4. **sticky + progress 패턴으로 만든다**(5절). 장면 길이만 바꿔서 템포를 조절한다.
5. **Playwright 로 스크린샷을 찍어 스스로 본다**(7절). 데스크톱, 375px 모바일, reduced-motion 세 조건.
6. 신영환에게 보여 주고 "더 해봐"가 나오면 장면을 늘리고 길이를 늘린다. 줄이지 않는다.

### 영상: ChatGPT 이미지 이어 붙이기 (2026-09-29 규칙 변경)

**Google Flow 는 더 쓰지 않는다.** Flow(Veo) 영상에는 우측 하단 ✦ 워터마크가 들어가고, 신영환이 VHS 에서 이를 지적했다(2026-09-29). 앞으로 영상이 필요하면 ChatGPT 프록시로 기준 이미지를 만들고, 그 이미지를 `refImagePaths` 로 넣어 같은 구도의 다음 키프레임을 여러 장 만든다. 움직임은 이미지 시퀀스 스크롤, 레이어 분리 패럴랙스, ffmpeg 크로스페이드·minterpolate 로 만든다. 워터마크를 크롭하거나 가리지 않는다. 아래 Flow 절은 기존 작품을 고칠 때만 참고한다.

## 5. 기법 레시피

### 스크롤 엔진 (전 페이지 공통)

```js
gsap.registerPlugin(ScrollTrigger);
const lenis = reduce ? null : new Lenis({ lerp: 0.08 });
if (lenis) { lenis.on('scroll', ScrollTrigger.update); gsap.ticker.add((t) => lenis.raf(t * 1000)); gsap.ticker.lagSmoothing(0); }
```

- CDN: `gsap@3.12.5`(gsap, ScrollTrigger), `lenis@1.1.13`, `three`. 폰트 Pretendard Variable.
- `lenis.velocity` 를 스크롤 속도로 쓴다. 마키 속도, 워프 늘어짐, 별가루 꼬리가 전부 이 값 하나에 묶여 있다. **속도에 반응하는 것**이 "살아 있다"는 느낌의 핵심이다.

### sticky 장면 패턴 (III 의 뼈대)

```html
<section class="scene" style="--len:500vh"><div class="sticky">...</div></section>
```
```css
.scene { position: relative; height: var(--len); }
.sticky { position: sticky; top: 0; height: 100vh; overflow: hidden; }
```
```js
ScrollTrigger.create({ trigger: el, start: 'top top', end: 'bottom bottom', onUpdate: (s) => draw(s.progress) });
```

- 장면 안에서는 `seg(p, a, b)` 로 구간을 자르고 `smooth()` 로 이징한다. 타임라인 라이브러리 없이 progress 하나로 모든 걸 그린다.
- III 장면 길이: AURORA 200vh, MORPH 1200vh, FOG 350vh, KINETIC 550vh, DIVE 500vh, PORTAL 400vh, DRIFT 500vh, PIXEL SORT 500vh, SPLIT 450vh, WARP 500vh, FAN 450vh, COUNT 350vh, 끝 650vh.
- 변신이 여러 번 일어나는 장면(MORPH, 6단계)은 1200vh 를 준다. 한 단계에 200vh 꼴이다.

### WebGL 렌더러 하나를 여러 장면이 나눠 쓴다

- 캔버스 하나를 fixed 로 깔고 `modes` 맵에 장면별 scene/camera 를 등록한다. 보이는 장면만 렌더한다(`onVisible` 토글). 장면마다 캔버스를 만들면 모바일에서 컨텍스트가 터진다.
- `setPixelRatio(Math.min(devicePixelRatio, 1.5))`, `antialias: false`.

### 파티클 모프 (II 8,000개, III 10,000개)

- 모양마다 목표 좌표 배열을 미리 만든다(구, 은하 나선, 토러스 매듭, 글자는 캔버스에 텍스트를 그려 픽셀을 샘플링, 하트, 얼굴은 이미지 밝기로 샘플링).
- ShaderMaterial 에 `aFrom`, `aTo` 속성을 주고 progress 로 mix 한다. `blending: THREE.AdditiveBlending`, `depthWrite: false` 여야 빛나는 느낌이 난다.
- 전환 중간에 노이즈로 흩어졌다 모이게 하면 "변신" 느낌이 산다.

### 이미지 시퀀스 스크롤 (2026-09-28, AFTER DARK IV)

애플 제품 페이지식 연출이다. 영상 `currentTime` 스크럽보다 프레임 이미지가 훨씬 부드럽다(키프레임 간격 문제가 없다).

- 재료: 완성 상태와 분해 상태 스틸 두 장을 먼저 만들고 Flow bridge(시작 이미지, 끝 이미지)로 8초 영상을 뽑는다. 레시피와 프롬프트는 README "AFTER DARK IV 재료".
- 인코딩: `ffmpeg -i ad4-explode.mp4 -vf scale=1280:-2 -c:v libwebp -quality 50 %03d.webp` → 1280x720, 192장, 장당 약 45KB, 합계 11MB.
- 점진 프리로드: 첫 장과 마지막 장, 그다음 16장 간격, 8, 4, 2, 1 간격 순서로 요청한다(동시 6개). 어느 시점이든 그릴 수 있는 프레임이 있고 해상도만 점점 촘촘해진다. `img.decode()` 로 디코드가 끝난 것만 쓴다.
- 그리기: 목표 인덱스에서 가장 가까운 로드된 프레임을 그린다. 그린 이미지가 바뀔 때만 다시 그린다(rAF 틱에서 비교). DPR 은 1.5 로 제한한다.
- 확대·팬은 캔버스를 다시 그리지 않고 CSS `transform` 으로 한다(1.0→1.12 줌, 재조립 장면은 1.35 배율로 좌우 팬). 콜아웃 좌표도 같은 변환을 계산해 따라간다.
- 콜아웃: 앵커는 마지막 프레임 기준 정규화 좌표, 라벨은 화면 %(가로·세로 화면 따로). SVG path 에 `pathLength=1` 을 주면 `stroke-dashoffset` 1→0 으로 선을 그을 수 있다.
- 프레임이 움직이는 동안 콜아웃을 붙이면 부품과 어긋난다. 그래서 ANATOMY 는 progress 0.04~0.70 에서 192장을 다 돌리고 나머지 30%(약 480vh)는 분해도를 멈춰 두고 콜아웃을 하나씩 띄운다.
- 세로 화면에서 cover 로 맞추면 16:9 프레임의 가운데 26% 만 보인다. 세로일 때는 가로 폭 맞춤 × 1.3 으로 그린다(프레임 배경이 검정이라 위아래가 자연스럽게 이어진다).
- reduced-motion 이면 마지막 프레임 한 장만 받고, 재조립 장면은 `assets/img/ad4/assembled.webp` 스틸을 보여 준다.

### AFTER DARK V 기법 (2026-09-28)

I~IV 에서 안 쓴 기법만 모았다. 장면 길이: RAYMARCH 450vh, LIQUID TYPE 400vh, SCULPTURE 900vh, DISPLACE 900vh, FLIGHT 900vh, PHYSICS 450vh, LINE 450vh, FINALE 400vh. 합계 4,850vh, 900px 화면에서 문서 높이 43,650px.
수치는 전부 `index.src.html` 의 `CONFIG` 에 있다. 아래는 결과를 좌우한 값과 실제로 걸린 함정이다.

**WebGL 캔버스 하나를 뷰포트 + 시저로 나눠 쓴다.** fixed 캔버스 하나에 Three.js 렌더러 하나. 장면마다 `{ pin, draw }` 를 등록하고 매 프레임 pin 의 `getBoundingClientRect()` 로 `setViewport(0, H - r.bottom, W, r.height)`, 보이는 부분만 `setScissor`. 두 장면이 화면을 반씩 나눠 쓰는 전환 구간도 자연스럽다. EffectComposer 의 마지막 패스도 렌더러 뷰포트를 따른다. 아무 장면도 안 보이면 한 번 지우고 렌더를 멈춘다. 렌더 틱은 모든 장면 틱보다 마지막에 등록한다.

**레이마칭.** 구 1개(반지름 .62) + 공 6개를 `smin`(k 는 합쳐졌을 때 .55, 흩어졌을 때 .26)으로 섞는다. 84스텝, 반사 광선은 28스텝 한 번 더. 환경은 텍스처 없이 방향 벡터로 만든다(수평 네온 띠, 천장 소프트박스, 마젠타·코발트 키라이트). 스크롤은 흩어짐(0.06~0.42)과 재결합(0.6~0.94), 카메라 궤도 0.75바퀴를 움직이고 포인터는 라임 스펙큘러 광원을 옮긴다. 해상도 0.5 로 그리면 1600px 에서 가장자리 계단이 보인다. 데스크톱 0.66, 모바일 0.5 로 저해상도 타깃에 그린 뒤 올려 붙인다.

**속도에 녹는 글자.** 목표값 `clamp(velocity * .02, -1, 1)` 에 스프링(강성 .085, 감쇠 .8)을 건다. 부호가 뒤집히며 튕기는 게 탄성 복귀다. 변위 scale 최대 110, skew 16도, scaleY 는 `1 + x * .45` 라 되돌아올 때 눌렸다 편다. 값이 .01 아래면 `filter: none` 으로 끈다(큰 글자에 필터를 계속 걸면 무겁다). 외곽선 줄은 가변 폰트 윤곽선 겹침이 보인다 → 채움을 배경색으로 두고 `paint-order: stroke fill`.

**파편 조각 + 후처리.** `IcosahedronGeometry(1.35, 2)` 는 비인덱스 180면이다. 면마다 바깥 삼각형과 .58 배 안쪽 삼각형을 이어 쐐기를 만들고 무게중심 기준으로 둔다. 메쉬 180개, `flatShading` + `DoubleSide` 라 감는 방향을 신경 쓸 필요가 없다. 폭발은 위쪽 조각부터 시차(.35)를 두고 바깥 1.4~3.4배로 날아가며 2~6라디안 돈다. RoomEnvironment 의 면광원 6개를 네온으로 다시 칠하고 방은 0x0b0b16 으로 어둡게 한 뒤 PMREM. **정면 면광원(원본 4번째)이 반사를 거의 다 차지한다.** 여기가 라임이면 조각 전체가 올리브색이 된다 → 코발트. 포인트 라이트는 물리 단위라 세기 60 이면 화면이 초록으로 번진다. 5 로 충분하다. 블룸 .55/.4/임계 .85, 색수차는 `.004 + |velocity| * .0012`(최대 .06)를 부드럽게 따라간다. 합성 타깃은 HalfFloat + samples 4.

**노이즈 변위 전환.** 이미지 5장, 전환 4번. `t = progress * 4` 의 소수부를 .3~.8 로 잘라 앞뒤 유지 구간을 둔다. 셰이더: `m = 1 - smoothstep(th-.12, th+.12, fbm*.75 + uv.x*.25)`, `th = mix*1.3 - .15` 라 0 과 1 에서 정확히 한 장만 보인다. A 는 mix 에 비례해, B 는 1-mix 에 비례해 반대 방향으로 밀린다(.35). 세로 화면은 가로 폭 맞춤 × 1.35 로 그려 위아래가 검은 띠가 되는데, 경계 글로가 그 띠에도 번진다 → 이미지 영역 마스크를 곱한다. `file://` 때문에 스틸은 `build.mjs` 가 data URI 로 넣는다(HTML 약 1.1MB).

**CSS 3D 비행.** 무대 `perspective: 800px`, 월드 `translateZ(800px) rotateX(pitch) rotateY(yaw) translate3d(-카메라)`. 카메라 z 는 700 → -5950, x·y 는 사인 곡선이고 yaw·pitch 는 경로 접선에서 구한다(부호: rotateY 양수가 오른쪽을 본다). 패널 6개는 z 간격 1100px, 폭 56vw(모바일 84vw). 거리 3800 에서 나타나 140 에서 사라지며 2400 안쪽일 때만 재생한다. `preload="none"` 이면 `play()` 가 곧 다운로드 시작이다. `<source>` 자식을 쓰면 로드 실패 이벤트가 video 가 아니라 source 에서 난다 → `src` 속성으로 넣는다. 일시정지할 때 Playwright 가 `ERR_ABORTED` 를 찍는데 범위 요청 취소라 정상이다. WebGL 이 아니라서 `file://` 에서도 영상이 그대로 나온다.

**Matter.js 글자.** span 박스로 바디를 만들면 글자가 바닥 아래로 절반 가라앉는다(줄 상자와 잉크 상자가 다르다). 캔버스 `measureText` 의 `actualBoundingBox*` 와 `fontBoundingBox*` 로 span 안의 잉크 상자를 구해 바디 크기로 쓰고, `transform-origin` 을 잉크 중심에 둔다. 중력은 `1 - clamp(velocity * .03, -1.5, 3)` 이라 빠르게 내리면 글자가 천장(화면 위 1.6배)으로 튄다. 포인터 반경 170px 안의 바디를 밀어낸다. progress .86 에서 바닥을 치워 글자를 떨어뜨리고, 되돌아오면 바닥을 다시 깔고 떨어진 글자를 위에서 다시 떨군다.

**선 드로잉.** 모든 선에 `pathLength=1`, 구간별 dashoffset 1→0. 한 path 에 눈금 144개를 이어 붙이면 눈금이 순서대로 켜진다. 별자리는 시드 PRNG(mulberry32)로 매번 같은 배치, 가까운 이웃 2개를 잇는다. V 두 팔 위에 별 9개를 두고 가는 선 → 굵은 라임 V(22px, drop-shadow) 순서. 끝에서 나머지를 .14 까지 어둡게 한다.

**기울기.** `DeviceOrientationEvent.requestPermission` 이 함수일 때만 "기울기 켜기" 버튼을 보이고 탭에서 권한을 요청한다(iOS). 안드로이드는 바로 듣는다. 첫 beta 를 기준으로 ±30도를 -1~1 로. 데스크톱은 포인터 위치가 같은 값을 만든다. Playwright 모바일 에뮬레이션(Chromium)도 이 함수를 노출해서 스크린샷에 버튼이 보인다.

**View Transitions.** 두 페이지 모두 `@view-transition { navigation: auto; }`. 목록의 V `.shot` 과 V 히어로 pin 에 `view-transition-name: ad5-hero`. 이름은 문서마다 하나여야 해서 V 항목에만 준다. 지원하지 않는 브라우저와 `file://` 에서는 그냥 일반 이동이다. reduced-motion 이면 애니메이션을 끈다.

**reduced-motion.** Lenis 끔, 셰이더는 고정 포즈로 스크롤이 있을 때만 다시 그림, 변위는 컷 전환, 비행은 포스터 격자, 물리는 바닥에 한 줄, 선은 완성본.

- **새 작품 배치는 배율 1.5(약 10,500vh)가 길었다.** 30~40% 줄이라고 해서 CHROME·SUMI·TOY TOWN 을 1.0(약 7,000vh)으로 낮췄다. AFTER DARK V(12,100vh)는 "이 정도면 됨"이었으니, 장면 밀도가 높으면 길어도 되고 밀도가 낮으면 7,000vh 안팎이 맞다
- **흰 바탕 작품은 빈 화면이 금방 생긴다.** SUMI 는 처음 20지점 중 5곳이 거의 백지였다. 장면 전환은 겹치게 하고, 여백은 "순간"으로만 쓴다. 검수는 에이전트 보고만 믿지 말고 균등 간격 20~40지점 샘플링으로 직접 본다.

- **공용 파일(루트 목록, README, 검사 스크립트)은 에이전트에게 맡기지 않는다.** 병렬 작업 뒤 한 번에 통합한다.
- 타이포만으로도 충분히 강한 작품이 나온다(SWISS). 재료 생성이 필수는 아니다.

## 6. 함정 (전부 실제로 걸림)

- **`file://` 로 열면 WebGL 이 외부 이미지를 못 읽는다**(캔버스 오염). 셰이더·샘플링에 쓰는 이미지는 빌드 때 data URI 로 넣는다 → `after-dark-3/build.mjs`. `index.html` 을 직접 고치지 말고 `index.src.html` 을 고친 뒤 빌드한다.
- Flow 에 공지 팝업("시작하기")이 새로 뜨면 원 파이프라인이 멈춘다. 720p 타일에는 `.resolution-badge` 가 없어서 완료 감지도 실패한다. `tools/flow-video.mjs` 가 둘 다 우회한다. 실패로 끝나도 영상은 만들어져 있을 수 있으니 `download` 모드로 받아 본다(크레딧 절약).
- 로마 숫자 I 같은 굵은 글자에 `-webkit-text-stroke` 만 주면 깨진 글자(□)처럼 보인다. 채운 색을 쓴다.
- `html, body { overflow-x: clip }` 을 넣지 않으면 흩어지는 글자와 틸트 카드 때문에 가로 스크롤이 생긴다.
- 스크롤 중(Lenis 보간 중)에 Playwright 스크린샷을 찍으면 fixed 요소와 본문이 어긋난 합성 화면이 찍힌다. 휠로 조금씩 내리고 1.5초 기다린 뒤 찍는다.
- Windows 에서 Python 한 줄 스크립트에 `C:\Users` 를 넣으면 유니코드 이스케이프 오류가 난다. 경로가 들어간 문서는 에디터 도구로 쓴다.

## 7. 검증 기준

- Playwright 로 데스크톱 1440, 모바일 375, reduced-motion 세 조건에서 연다. 콘솔 오류 0건, 404 0건, `scrollWidth > innerWidth` 거짓이어야 한다.

- reduced-motion 이면 Lenis 를 끄고 파티클은 최종 형태만, 영상은 포스터만 보여 준다.
